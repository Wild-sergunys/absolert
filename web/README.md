# Веб-интерфейс Absolert

Панель на React и TypeScript. `/monitor` показывает алерты и состояние сенсора.
На `/` открыт учебный режим с примером графика, разбором события и черновиками
сигнатур. Учебные данные, переключатели и черновики не влияют на захват.

## Мониторинг с сенсором

Нужна версия Node.js из [`.nvmrc`](.nvmrc). Из корня репозитория, обычным
пользователем:

```bash
make web-install
make build web-build
./bin/absolert-api
```

Откройте <http://127.0.0.1:8090/monitor>. API печатает путь к сокету;
по умолчанию это `$XDG_RUNTIME_DIR/absolert.sock`. Если переменная не задана,
создайте закрытый каталог через `mktemp -d` и укажите путь к сокету внутри него
во флаге `--socket`.

Во втором терминале запустите контрольную запись:

```bash
./bin/absolert --pcap internal/sensor/testdata/et-tcp-scan.pcap \
  --rules configs/rules/et-tcp-scan.rules --home-net 192.0.2.2/32 \
  --api-socket "$XDG_RUNTIME_DIR/absolert.sock"
```

Подставьте в `--api-socket` фактический путь, если он отличается. В ленте
появятся восемь алертов с пометкой «Запись PCAP». Для живой проверки используйте
[инструкцию стенда](../docs/LAB.md#проверка-алерта-в-браузере).
Ctrl+C останавливает запущенный процесс. При перезапуске API история обнуляется.

## Разработка

```bash
make web-install
make web-dev
```

Vite раздаёт учебный режим на <http://127.0.0.1:5173>. `make web-test` проверяет
логику интерфейса, `make web-build` проверяет типы и собирает `web/dist`.
Зависимости и сборка не добавляются в Git; точные версии хранятся
в `package-lock.json`.

Учебные события используют адреса RFC 5737 и вымышленные SID. Фильтры,
состояние разбора и черновики живут в памяти вкладки. Экспорт содержит пометку
демонстрационного режима. Настоящие алерты отображаются отдельно и не смешиваются
с учебными событиями.
