# Лабораторный стенд

## Схема и проверенный результат

```text
MacBook + USB Ethernet-адаптер
         │ Ethernet
Linux: тестовый HTTP-сервер и Absolert
```

14 ноября 2026 года проверены ICMP, HTTP и двунаправленный обмен через tcpdump.
16 ноября Absolert увидел входящие SYN, установление TCP-соединения, передачу
данных и закрытие. После Ctrl+C: 119 прочитанных пакетов = 13 TCP + 106
неподдерживаемых, повреждённых и усечённых нет. libpcap сообщил нулевые потери;
это результат небольшого эксперимента, а не измерение предельной нагрузки.

Linux сам получатель обмена. Это наблюдение доступного хосту трафика, а не
проверка SPAN/TAP или транзитного периметра. Попытка подключения может быть
видна сенсору до решения локального фаервола. Успешная эксплуатация не требуется
для обнаружения попытки; доступный порт сам по себе не означает уязвимость.

## Почему первоначально не было соединения

Использовались временные адреса через `ip addr` и `ifconfig`, а разрешение
firewalld действовало только 10 минут. Во время повторной проверки порт 8088
также никто не слушал. После восстановления адресов, запуска сервера и разрешения
входящего подключения HTTP заработал. Поэтому состояние сети, сервер и фаервол
проверяются отдельно.

## Сохранённая конфигурация от 16 ноября

Адреса ниже относятся к выделенной лабораторной подсети, а не к домашней сети.
Имена интерфейсов зависят от машины; личные адреса, MAC и дампы не публикуются.

| Параметр | Linux | Mac |
|---|---|---|
| Интерфейс текущего стенда | enp3s0 | en6 |
| Профиль / служба | ids-lab | USB 10/100/1000 LAN |
| IPv4 | 192.168.77.1/24 | 192.168.77.2/24 |
| Шлюз лабораторной сети | Не задан | Не задан |
| Интернет | Wi-Fi | Wi-Fi |

### Linux: профиль NetworkManager

Существующий профиль `enp3s0` переименован в `ids-lab`, автоподключение уже было
включено. Следующие команды описывают выполненную настройку, а не обязательный
повтор при каждом запуске. Если профиль уже называется `ids-lab`, используйте
его имя в первой команде вместо `enp3s0`.

```bash
sudo nmcli connection modify enp3s0 \
  connection.id ids-lab \
  ipv4.method manual \
  ipv4.addresses 192.168.77.1/24 \
  ipv4.gateway "" \
  ipv4.dns "" \
  ipv4.never-default yes \
  ipv6.gateway "" \
  ipv6.dns "" \
  ipv6.ignore-auto-dns yes \
  ipv6.never-default yes
sudo nmcli connection up ids-lab
```

`never-default` не позволяет Ethernet становиться основным маршрутом. Шлюз и DNS
стенда не задаются. Другой неактивный Ethernet-профиль не удалялся; при проблеме
автоподключения сначала проверьте, какой профиль действительно активен.

### Mac: сохранённый ручной адрес

В «Настройки системы → Сеть → USB 10/100/1000 LAN → Подробнее → TCP/IP» выбраны:
IPv4 вручную, адрес `192.168.77.2`, маска `255.255.255.0`, поле маршрутизатора
пустое. Настройка относится к службе адаптера; если он используется в другой
сети, потребуется вернуть DHCP либо переключить сетевую конфигурацию.

Проверены связь после переподключения кабеля и работа интернета через Wi-Fi.
Поведение после перезагрузки обеих машин ещё не проверялось.

### Linux: отдельная зона firewalld

Создана постоянная зона `ids-lab`, в ней разрешён только тестовый TCP-порт
8088 от адреса Mac к адресу Linux. Это узкое разрешение входящего TCP;
прочий трафик обрабатывается обычными правилами зоны, а не обещанием запрета
всех остальных протоколов. Зона привязана к профилю NetworkManager.

```bash
sudo firewall-cmd --permanent --new-zone=ids-lab
sudo firewall-cmd --permanent --zone=ids-lab \
  --add-rich-rule='rule family="ipv4" source address="192.168.77.2/32" destination address="192.168.77.1/32" port port="8088" protocol="tcp" accept'
sudo firewall-cmd --check-config
sudo firewall-cmd --reload
sudo nmcli connection modify ids-lab connection.zone ids-lab
sudo nmcli connection up ids-lab
```

Создание зоны выполняется один раз. `--reload` заменяет runtime-конфигурацию
постоянной и удаляет несохранённые временные правила. Постоянное разрешение
не истекает через 10 минут. Проверка привязки:

```bash
sudo firewall-cmd --get-zone-of-interface=enp3s0
```

Ожидается `ids-lab`. После применения зоны подтверждён HTTP GET 200 с Mac.
Также проверен запуск через `make lab-server LAB_BIND=192.168.77.1`: сервер
ответил 200 на запрос с Mac.

## Повторный запуск эксперимента

1. Подключить кабель и дождаться линка. При необходимости на Linux выполнить
   `sudo nmcli connection up ids-lab`.
2. Проверить связь с Mac:

   ```bash
   ping -c 4 -S 192.168.77.2 192.168.77.1
   ```

3. На Linux из корня проекта запустить пустой тестовый сервер:

   ```bash
   make lab-server LAB_BIND=192.168.77.1
   ```

   Требуется Python 3. По умолчанию `make lab-server` слушает только loopback.
   `LAB_PORT` позволяет выбрать порт, но правило firewalld разрешает именно 8088.
   Сервер не меняет адреса, маршруты или фаервол и не раздаёт файлы проекта.
   Временный каталог удаляется при обычном завершении, включая Ctrl+C.
   Это сервер диагностики HTTP, не уязвимое приложение для эксплуатации.

4. В другом терминале Linux:

   ```bash
   make build
   sudo ./bin/absolert --interface enp3s0
   ```

5. На Mac:

   ```bash
   curl --noproxy '*' --connect-timeout 3 -i http://192.168.77.1:8088/
   ```

6. Проверить ответ 200 и TCP-записи сенсора. Остановить сервер и сенсор через
   Ctrl+C. Не публиковать вывод с личными адресами из других сетей.

Если нет связи: сначала линк и адреса, затем маршрут и ping, затем слушающий
сервер (`ss -ltn 'sport = :8088'`), локальный curl и зона firewalld. Наличие
SYN в Absolert означает, что попытка дошла до интерфейса; это ещё не HTTP-ответ.

## Отключение и возврат

Для временного отключения профиля без удаления настроек:

```bash
sudo nmcli connection modify ids-lab connection.autoconnect no
sudo nmcli connection down ids-lab
```

Повторная активация: `sudo nmcli connection up ids-lab`. Если нужно вернуть
автоподключение: `sudo nmcli connection modify ids-lab connection.autoconnect yes`.

Для удаления разрешения HTTP из активной и постоянной конфигураций:

```bash
sudo firewall-cmd --zone=ids-lab \
  --remove-rich-rule='rule family="ipv4" source address="192.168.77.2/32" destination address="192.168.77.1/32" port port="8088" protocol="tcp" accept'
sudo firewall-cmd --permanent --zone=ids-lab \
  --remove-rich-rule='rule family="ipv4" source address="192.168.77.2/32" destination address="192.168.77.1/32" port port="8088" protocol="tcp" accept'
```

Профиль и зона при этом сохраняются. На Mac возврат службы адаптера к DHCP
делается в том же разделе TCP/IP. Эти действия отключают стенд; перед применением
нужно завершить эксперимент. Полное восстановление прежней конфигурации Linux
не автоматизировано: прежние настройки не экспортировались.
