# Правила Suricata в Absolert

## Набор правил

При запуске с `--rules` сенсор загружает файл целиком, проверяет поддерживаемые
условия и применяет их к наблюдениям TCP. В этом режиме в терминал выводятся
алерты и итоговые счётчики. Все три правила сверены с Suricata 8.0.2 на
контрольном PCAP. Живой алерт VNC можно повторить по
[инструкции стенда](LAB.md#проверка-алерта-в-браузере).

Набор `configs/rules/et-tcp-scan.rules` содержит три неизменённые строки ET Open
и исходное уведомление об авторских правах и BSD-лицензии. Лицензия MIT проекта
не заменяет лицензию этого файла.

## Источник и идентичность правила

- Источник: https://rules.emergingthreats.net/open/suricata-8.0/rules/emerging-scan.rules
- Версия сравнения — **Suricata 8.0.2**.

| SID:rev | Условие пакета | Когда выдаётся алерт по источнику |
| --- | --- | --- |
| 2002910:6 | SYN к 5800–5820, ECN игнорируется | На пятом совпадении за 60 с (`both`) |
| 2001219:20 | SYN к 22, ECN игнорируется | На пятом совпадении за 120 с (`both`) |
| 2010939:3 | SYN к 5432, без дополнительных флагов | На первых пяти совпадениях за 60 с (`limit`) |

В SHA-256 ниже учитывается строка правила без завершающего переноса:

- 2002910: `d492c62110bc47460ab5546f6a0757d17da29fbf18e351a31877d06ef12a46c9`.
- 2001219: `02fcd2ab9218fe2e700f4d95d4d4dc05b043c85218a05ccd3cff2f15bc052479`.
- 2010939: `f6ddd488f996062734f71994cf1557b8071972cc02fc4b261c8191a39d41bb0a`.

Окно начинается с первого совпадения и включает точную правую границу.
После неё следующее совпадение начинает новое окно. Это поведение сверено по
исходнику Suricata 8.0.2. В алерте указывается фактическое число совпадений.

Повторные попытки к одному порту учитываются. Правила не требуют успешного
соединения и не доказывают сканирование разных портов или компрометацию узла.

## Грамматика текущего загрузчика

- Одна активная строка на правило. Пустые строки и строки с начальным `#`
  пропускаются. Продолжения строк и комментарии в конце активной строки не поддержаны.
- Заголовок: `alert tcp SRC PORT -> DST PORT`.
- Сети: `any`, `$HOME_NET`, `$EXTERNAL_NET`. Загрузчик читает эти значения;
  исполнитель пока принимает только направление `$EXTERNAL_NET → $HOME_NET`.
- Порты: `any`, одно число 0–65535 или включительный диапазон `START:END`.
  Списки, отрицания и переменные портов пока отклоняются.
- Обязательные опции: `msg`, `sid`, `rev`, `flow:to_server`, `flags:S` либо
  `flags:S,12`, `threshold` типа `both` или `limit` с `track by_src`, `count`
  и `seconds`, `classtype`.
- `metadata` и одна опция `reference:тип,значение` необязательны. Они хранятся
  как описательная информация и не влияют на совпадение.
- `msg` — непустая строка в двойных кавычках. Поддержано экранирование двойной
  кавычки и обратной косой черты; управляющие символы запрещены.
- SID, rev, count и seconds — положительные 32-битные целые числа.
- Повторные опции, повторные SID и неизвестные условия делают весь файл
  недопустимым.
- Лимиты: файл до 1 МиБ, строка менее 64 КиБ, не более 1024 активных правил.

## Запуск и ограничения исполнения

```bash
make build
sudo ./bin/absolert --interface enp3s0 \
  --rules configs/rules/et-tcp-scan.rules --home-net 192.0.2.10/32
```

Подставьте в `--home-net` адрес защищаемого узла. Если источник и цель находятся
в одной подсети, используйте адрес цели с маской `/32`: `$EXTERNAL_NET` означает
все IPv4-адреса вне этого префикса. Без этих двух флагов сохраняется режим
диагностики пакетов.

Направление клиента к серверу определяется для входящего начального SYN.
Исполнитель пока не ведёт таблицу TCP-соединений. Окна считаются отдельно
по SID и IP источника, по времени захвата. Всего удерживается до 4096 окон;
истёкшие окна удаляются при обработке трафика не чаще раза в секунду. Если
лимит исчерпан, новые окна пропускаются. Отметки времени, идущие назад, тоже
пропускаются; оба случая отражаются в итоговых счётчиках.

## Офлайн-проверка и сравнение

```bash
make build
TZ=UTC ./bin/absolert --pcap internal/sensor/testdata/et-tcp-scan.pcap \
  --rules configs/rules/et-tcp-scan.rules --home-net 192.0.2.2/32
```

`--pcap` заменяет `--interface`. Офлайн-режим не открывает сетевой интерфейс,
читает Ethernet-кадры до конца файла и использует их исходные отметки времени.
Итог содержит счётчики обработки, без статистики потерь живого захвата.

Фикстура — 32 синтетических Ethernet-кадра без прикладных данных, с адресами из
RFC 5737. В ней есть совпадения всех трёх правил, контрольный трафик, ECN,
SYN-ACK и пакеты ровно на границе окна и после неё. SHA-256 файла:
`83a541fe7e81400aa0258d87c7330921ec1371c822a7e359ee1a511e0f30a0b6`.
`go test ./internal/sensor -run '^TestReplayETRules$'` проверяет весь путь
от чтения файла до консольных алертов.

Для сравнения Suricata 8.0.2 запускалась в режиме `single` с теми же сетевыми
переменными, только этим файлом правил (`-S`) и тем же входом (`-r`).
У всех восьми алертов совпали отметки времени, SID, ревизии, адреса и порты:
один VNC, один SSH, шесть PostgreSQL (пять в первом окне, один после границы).
Результат относится к этому контролируемому входу и выбранным правилам.
