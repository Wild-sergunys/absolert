# Absolert

Absolert — пассивная система обнаружения вторжений (IDS) на Go для исследования
трафика на внешнем периметре промышленной вычислительной сети. Это дипломный
проект с собственным движком и локальной панелью. Сенсор наблюдает за трафиком
и выдаёт алерты.

Название объединяет **Absol**, покемона, который чувствует приближение опасности,
и **alert** — оповещение.

## Что работает

- Сенсор читает Ethernet / IPv4 / TCP с интерфейса Linux или из сохранённого
  PCAP. Он выводит диагностику либо исполняет выбранный набор правил.
- В комплекте три оригинальных правила ET Open: для VNC, SSH и PostgreSQL.
  На контрольной записи Absolert и Suricata 8.0.2 выдали одинаковые восемь
  алертов. [Правила и методика сравнения](docs/RULES.md).
- Локальная панель показывает состояние сенсора, счётчики и причину алерта.
  На стенде Mac → Linux два живых алерта VNC дошли до браузера без перезагрузки.
  [Протокол проверки на стенде](docs/LAB.md#проверка-алерта-в-браузере).

## Сборка и проверки

Требуются Go версии из `go.mod`, C-компилятор, заголовки и библиотека libpcap.
Для EndeavourOS/Arch: `sudo pacman -S --needed base-devel libpcap`.
Для Ubuntu/Debian: `sudo apt-get install build-essential libpcap-dev`.
Проверка библиотеки: `pkg-config --modversion libpcap`. Сборка использует CGO.

```bash
make build
make test
make lint
```

`make build` собирает сенсор `bin/absolert`, локальный API `bin/absolert-api`
и тестовый сервер `bin/absolert-lab`. Для `make lint`
используйте golangci-lint **2.15.0**, собранный Go 1.27 или новее. CI использует
ту же версию линтера и читает версию Go из `go.mod`. Если первым в `PATH`
находится старый линтер, передайте путь к нужному бинарнику:

```bash
make lint GOLANGCI_LINT="$HOME/.local/bin/golangci-lint"
```

## Первый запуск без сетевого захвата

После `make build` прогоните синтетическую запись без `sudo`:

```bash
./bin/absolert --pcap internal/sensor/testdata/et-tcp-scan.pcap \
  --rules configs/rules/et-tcp-scan.rules --home-net 192.0.2.2/32
```

Ожидаемый итог: **32 пакета и 8 алертов**, затем сенсор завершится. Без
`--rules` сенсор выводит заголовки TCP вместо алертов.

## Мониторинг в браузере

Установите Node.js по версии из [`web/.nvmrc`](web/.nvmrc), затем из корня проекта
запустите сборку и API обычным пользователем:

```bash
make build web-install web-build
./bin/absolert-api
```

Откройте <http://127.0.0.1:8090/monitor>. Во втором терминале запустите сенсор
с `--api-socket "$XDG_RUNTIME_DIR/absolert.sock"` или путём, который напечатал
API. Для живого захвата укажите `--interface` вместо `--pcap` и префикс
своего стенда в `--home-net`. Права захвата нужны только сенсору.

[Инструкция запуска панели](web/README.md#мониторинг-с-сенсором) ·
[Сценарий для Mac и Linux](docs/LAB.md#проверка-алерта-в-браузере).

## Ограничения

- Исполнитель поддерживает [поднабор правил Suricata](docs/RULES.md). Порог
  считается по IP источника и учитывает повторные попытки к одному порту.
- Сенсор анализирует Ethernet без VLAN и нефрагментированный IPv4/TCP.
  Зеркалирование транзитного трафика на стенде не проверялось. Сборка TCP-потоков,
  анализ HTTP и проверка под нагрузкой остаются в плане.
- API слушает только локальный адрес и хранит последние 100 алертов в памяти.
  При недоступности API сенсор продолжает анализ и считает потери доставки.
  Содержимое пакетов не передаётся в браузер и не сохраняется.
