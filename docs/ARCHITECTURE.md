# Архитектура Absolert

Absolert наблюдает за доступным сенсору трафиком и выдаёт алерты. Сенсор
не меняет пакеты и параметры сети. На стенде он видит обмен с самим Linux;
транзитный трафик через SPAN или TAP здесь не проверяется.

## От пакета до алерта

```text
Интерфейс Linux или PCAP → libpcap → Ethernet / IPv4 / TCP
  → условия правила и порог → алерт → Unix-сокет → локальный API → браузер
```

Живой захват и чтение файла используют один последовательный цикл. На Linux
сенсор открывает интерфейс через `pcap.OpenLive` с длиной захвата 65 535 байт,
без promiscuous mode и с ожиданием чтения до 100 мс. Между чтениями цикл
проверяет отмену. Вход с канальным уровнем, отличным от Ethernet, отклоняется.
VLAN, IPv6 и фрагменты IPv4 не анализируются. Усечённые и повреждённые кадры
учитываются отдельно.

Декодер передаёт детектору `packet.TCP`: отметку времени, адреса, порты и флаги.
Содержимое пакетов не сохраняется. Контрольные суммы не проверяются: в локальном
захвате пакет может быть виден до того, как сетевая карта вычислит сумму.

## Правила

Загрузчик читает один файл `.rules` и отклоняет его целиком, если встречает
неподдерживаемое условие или повторный SID. Исполнитель проверяет заголовок
и флаги, затем считает совпадения по паре «SID и IP источника». Окно отсчитывается
по времени захвата; скорость чтения PCAP на результат не влияет. При убывающей
метке времени пакет пропускается детектором. В памяти удерживается не более
4096 окон, истёкшие записи удаляются при обработке следующих пакетов.

В комплекте три правила ET Open. Они учитывают повторные попытки к одному
порту и не подтверждают успешное вторжение. Точное поведение порогов, границы
поддержки и сравнение с Suricata описаны в [описании правил](RULES.md).

## Доставка и просмотр

Сенсор отправляет алерты и отчёты в датаграммный Unix-сокет в закрытом каталоге
пользователя. Отправка неблокирующая, очередь ограничена ядром. Если сокет
недоступен, очередь заполнена или сообщение превышает 16 КиБ, алерт
учитывается как недоставленный. Пропущенные алерты не повторяются. Ошибки
доставки, потери захвата и ошибки декодирования считаются отдельно.

API запускается без прав захвата на `127.0.0.1:8090`. Он раздаёт сборку
из `web/dist`, хранит последние 100 алертов и последний отчёт сенсора.
Страница `/monitor` опрашивает `GET /api/monitor` раз в секунду. Если работающий
сенсор не прислал отчёт за четыре секунды, интерфейс показывает «Сенсор не
отвечает». Для PCAP отдельно отображаются завершение, остановка и ошибка
чтения. Учебный режим на `/` использует отдельные данные.

## Где искать код

| Каталог | Ответственность |
| --- | --- |
| `cmd/absolert` | Параметры запуска и завершение сенсора |
| `internal/capture` | Открытие интерфейса и файлов PCAP |
| `internal/packet` | Декодирование заголовков |
| `internal/rules`, `internal/detect` | Загрузка правил и проверка совпадений |
| `internal/sensor` | Связь захвата, детектора и вывода |
| `internal/monitor`, `cmd/absolert-api` | Доставка, история в памяти и локальный HTTP API |
| `web` | Интерфейс мониторинга и учебный режим |
| `configs/rules` | Исходные правила и лицензия ET Open |

Проверки Go находятся рядом с кодом. Контрольный PCAP из синтетических кадров
лежит в `internal/sensor/testdata`; реальные дампы в репозиторий не добавляются.

Для анализа HTTP нужны сборка TCP-потоков и разбор сообщений с ограничениями
по памяти. Поддержку планируется наращивать по выбранным правилам Suricata
и проверять на контрольных записях. Хранение истории в PostgreSQL и измерения
под нагрузкой — отдельные задачи [плана разработки](ROADMAP.md).
